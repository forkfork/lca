# 512 MiB MicroVM baseline: further validation

The same frozen AL2027 artifact successfully built at a 512 MiB / 0.25 vCPU
baseline in Sydney and completed both existing smoke tasks in one actual VM.
The coding task repaired clamp.lua, used Git and passed the original tests and
the exhaustive 9,471-case grader. Extracted artifacts independently passed those
tests again on the host, with README.md and test.lua unchanged.

| Task | Model calls | Tool calls | Wall seconds | CPU seconds | CPU / one core | CPU / 0.25-core baseline | Sampled process-tree RSS peak |
|---|---:|---:|---:|---:|---:|---:|---:|
| Read-only | 2 | 2 | 8.897 | 0.148 | 1.66% | 6.65% | 22.91 MiB |
| Coding | 4 | 6 | 17.986 | 0.216 | 1.20% | 4.80% | 24.36 MiB |

CPU is Bash `time` user + system time for the smoke script and descendants,
including setup, LCA, local tool commands and independent grading. Wall time
includes model waits. Percentages are whole-task averages, not instantaneous
peaks or AWS billable utilization. The separate Lua sampler reads /proc once
per second; its own CPU is excluded from the timed task. Process-tree RSS adds
resident pages across live descendants and may double-count shared pages or
miss peaks between samples. It does not include the whole VM or filesystem
cache. No TUI animation ran: the unchanged smoke script invokes `lca run`.

AWS configuration confirms a 512 MiB baseline, but guest /proc/meminfo reports
2,037,648 KiB total, reflecting burst-capable guest capacity. The standard
/sys/fs/cgroup CPU and memory counters were unavailable in this application
environment. Consequently, this test does not establish a hard 512 MiB memory
limit, absence of resource bursts, or exact charged resource usage. There were
no task failures, but no cgroup OOM-event measurement was available.

The telemetry sampler passed an offline child-process/timer test in the existing
x86 container. The initial host-only preflight could not load luv; it made no
model calls. Live testing used gpt-6-astra, medium reasoning, priority service,
with the existing fixture and prompts. Usage: read-only 14,903 input / 83 output
tokens; coding 31,624 input / 348 output tokens. Six model calls total, eight
tool calls. OAuth monetary cost and AWS charges were not measured.
