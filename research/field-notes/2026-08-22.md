# Research scan — 2026-08-22

Scope: edit tools and context lifecycle. This initial scan mixed pinned source,
vendor material, and a small number of community threads. It did not consistently
record publication dates, so retrieval date must not be interpreted as freshness.
The corrected research method starts with a trailing-90-day HN/Reddit/X feed and uses
source inspection plus LCA evals for validation.

## High-confidence findings

- Pi's implementation has evolved beyond a naive string replacement: multiple
  disjoint replacements share one original snapshot, ambiguity is rejected, matching
  has bounded normalization, original file representation is preserved, and file
  mutation is serialized. [pi-edit] [pi-edit-diff]
- Codex's patch grammar is a model-facing product surface, not merely shelling out to
  arbitrary `patch`; its instructions and runtime treat file operations, safety, and
  protocol events as first-class concepts. [codex-patch] [codex-source]
- Aider maintains multiple edit formats because format following is model-dependent.
  Its benchmark separates successful task completion from valid edit formatting.
  [aider-edit-formats] [aider-benchmarks]
- Pi keeps a recent verbatim tail and durable full session state while summarizing
  older work. Claude Code recommends clearing unrelated tasks and isolating verbose
  research. Codex prioritizes exact prompt-prefix stability for caching and compacts
  when a threshold is crossed. [pi-compaction] [anthropic-best-practices] [codex-loop]

## Emerging ideas

- Semantic phase boundaries may be better compaction points than token pressure alone.
- A durable structured checkpoint should be partly machine-derived, because the agent
  can incorrectly summarize whether a test passed or a file changed.
- Periodically rebuilding active state from original goal + worktree + verification may
  avoid recursive-summary drift.
- Capability discovery metadata can stay small while full tool/skill schemas load on
  demand, but prompt-cache effects must be measured. [factory-deferred-context]
- Fresh-context workers are promising for verbose exploration and adversarial review,
  but likely wasteful for small dependent edits. [anthropic-best-practices]
- Anthropic reports removing over 80% of Claude Code's system prompt for its newest
  models without measurable loss on its coding evals. Combined with recent context-file
  ablation and configuration-smell studies, this makes LCA prompt reduction a serious
  eval target rather than aesthetic cleanup. [claude-context-rules-2026]
  [context-files-ablation] [agents-md-smells]

## Field-report signals

- HN and Reddit users disagree sharply on compaction quality. Several prefer reviewed
  handoff files and fresh sessions; others report good results across multiple
  compactions when a single scoped task is anchored by an updated plan.
- Recent Pi maintainer posts emphasize customizable compaction, extension-level tools,
  turn-end rather than per-edit LSP feedback, and steering while compaction runs.
- These reports identify eval cases—lost constraints, stale assumptions, context bloat,
  and over-delegation—but do not establish optimal thresholds.

## Method correction

- Vendor best-practice pages in this scan are baselines, not the innovation feed.
- Several entries in `sources.json` lack `published_at`; those sources are not entitled
  to a "recent" label until dated.
- A follow-up native web scan surfaced materially sharper current reports: Codex users
  seeing compaction every 10–20 minutes, fresh-session handoff workflows, long-running
  orchestrators that do no implementation work themselves, custom editorial
  compaction, and a Pi failure near the context limit during multi-tool turns.
  [reddit-codex-frequent-compaction-2026-08]
  [reddit-long-running-agents-2026-08] [hn-pi-minimalism-2026-08]
- These reports generate concrete eval hypotheses: compaction latency and frequency,
  survival of last-minute steering, turn-boundary overflow, clean-session handoff
  fidelity, and orchestrator context growth.
- Focused X web-index queries returned no qualifying posts inside the trailing 90-day
  window. This is a coverage gap, not evidence that X had no relevant discussion; a
  future refresh needs direct account/list search or an X-capable index and must still
  enforce the same publication-date cutoff.

## Immediate LCA implications

1. Evaluate multi-edit exact replacement before adopting a generic patch parser.
2. Add long-horizon evals that compare rolling compaction to a fresh goal/checkpoint
   rebase.
3. Make context correctness observable through trajectory/workspace checks rather than
   self-reported memory questions.
4. Track total task cost, redundant reads, retries, stale edit failures, and cache
   behavior alongside pass/fail.
